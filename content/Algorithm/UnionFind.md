## Uinon Find
유니온 파인드 알고리즘은 대표적인 `Graph 알고리즘` 중 하나 중 하나이며, 여러 노드가 존재할 때 어떤 `두 개의 노드를 같은 집합으로 합치고, 어떤 두 노드가 같은 집합에 있는지 확인하는 알고리즘`입니다. 반대로 서로 연결되어 있지 않은 노드를 판별할 수도 있기 때문에 `상호 배타적 집합 (Disjoint-Set)` 라고도 불립니다. 알고리즘 이름에서 유추할 수 있듯, 유니온 파인드 알고리즘은 두가지의 연산을 사용합니다.

- `Union` : 서로 다른 두 노드가 속한 집합을 하나의 집합으로 합치는(합집합) 연산을 말합니다.
- `Find` : 어떤 하나의 원소가 속하는 집합을 찾는 연산을 말합니다.

> [!note] 집합 & 상호 배타적 집합
> 집합 : 순서와 중복이 없는 자료구조를 말합니다.
> 상호 배타적 집합 : 교집합이 없는 집합을 말합니다.

## 집합의 표현
집합을 합치거나 탐색하는 연산을 수행하기 위해서는 집합을 표현할 줄 알아야 합니다. 보통 `집합은 트리로 표현하며 이는 배열로 표현`할 수 있습니다. 집합을 배열로 표현할 때, `각 집합에는 대표원소`가 있어야 합니다.

> [!note] 대표원소
> 대표원소는 집합을 이루는 원소들 중 집합을 대표할 수 있는 원소를 의미합니다. 이는 특정 집합의 Root Node 와 같은 의미입니다.


서로 다른 집합 두개를 트리를 이용한 배열에 표현하는 예를 한번 보겠습니다. 집합 A를 트리를 이용한 배열로 표현하면, 아래와 같이 나타낼 수 있습니다. 

- `노드 2` 는 집합 A의 대표원소이자 루트노드입니다. (배열의 Index 와 Value 값이 동일합니다.)
- 배열의 `Index 는 현재 노드를 의미`하며 배열의 `Value 는 현재 노드의 Parent 노드를 의미`합니다. (의사코드로는 `Tree[현재노드] = 부모노드`)

### 배열의 초기화
앞서 서로 다른 두 집합을 하나의 배열에 표현하는 예제는 살펴보았습니다. 이 배열을 처음에 어떻게 초기화해야 할까요? 

- 배열의 크기는 집합들의 모든 원소들 중 가장 큰 값을 담을 수 있는 크기를 설정합니다.
- 배열의 초기값은 현재 노드와 부모노드 값을 자기 자신으로 설정합니다. (의사코드로는 `Tree[현재 노드] = 현재노드`)
- 이 때, Index 0 번 노드는 잘 사용하지 않으니 값을 설정하지 않거나 -1 로 설정합니다. (`아예 안해도 되는 과정입니다.`)

### Find 연산 과정
파인드 연산은 특정 노드가 속한 집합의 대표원소를 찾는 연산입니다. Union 연산보다 Find 연산을 먼저 알아보는 이유는 `Union 연산에서 Find 연산이 필요`하기 때문입니다. 

- 현재 노드에서 시작해서, 그 노드의 부모를 따라 계속 올라가며, 부모 노드와 자기 자신이 같아질 때까지 탐색을 반복합니다.

예를 들어 `노드 3` 이 속한 집합의 대표원소를 찾는 예시를 들어보면 `2` 가 나옵니다. 

![](Algorithm/images/Pasted%20image%2020250531001702.png)


### Union 연산 과정
유니온 연산은 두 노드가 속한 서로 다른 두 집합을 하나의 집합으로 합치는 연산입니다. 

1. 두 노드가 속한 집합의 대표원소(Root 노드) 를 `Find` 합니다. 
	- 이 때, 두 대표원소의 값이 같다면, Find 연산을 진행한 두 노드는 이미 같은 집합에 속해있다는 것을 의미합니다.
	- 반대로 두 대표원소의 값이 다르면, Find 연산을 진행한 두 노드는 서로 다른 집합에 속해있는 것을 의미합니다.
2. 두 대표원소의 값이 달라 두 노드가 속한 집합이 상호 배타적이면 합칠 수 있습니다. 이 때 `한쪽 대표 노드를 다른 쪽의 부모로 설정하여 두 집합을 합칩니다.`
	- 물론 두 대표 원소가 같아도 union 연산을 수행해도 무방하지만, 이는 `불필요한 연산`입니다.
	- 특히 사이클 여부를 판단하는 문제에서는 대표 원소가 다를 때만 Union 을 수행해야 사이클 생성을 정확히 탐지할 수 있습니다.


#### 루트 노드 설정 기준
집합을 합칠 때는 `한쪽 대표 노드를 다른 쪽의 부모로 설정`하여 트리를 구성합니다. 이때 `어느 쪽을 부모로 삼을지를 정하는 기준`은 크게 두가지가 있습니다.

1. `고정된 방향으로 합치기` 
	- 항상 root1 을 root2 의 부모로 정하거나 그 반대로 고정합니다.
	- 이 방식은 두 집합을 `합치는 순서에 따라 트리의 구조가 달라질 수 있습니다.`
2. `값의 크기를 기준으로 합치기`
	- 대표 노드 중 값이 더 작은 쪽을 부모로 설정하거나, 그 반대로 합칩니다.
	- 이 방식은 두 집합을 합치는 순서에 관계없이 트리의 구조가 일정합니다.


아래 그림에서 `노드 3 과 노드 8` 이 속한 두 집합의 대표원소는 `2 와 4` 입니다. 이 두 대표원소는 값이 다르기 때문에 노드 3 과 노드 8 은 서로 다른 집합에 속해있는 것을 판단할 수 있습니다. 이제 집합을 합치면 됩니다.

> [!note] 항상 root1 이 root2 의 부모로 정하는 방식을 사용합니다.
> 합치기 전 집합 A 는 노드의 크기에 상관없이 구성되어있습니다. 이 뜻은 집합 A 를 구성할 때, 노드의 크기를 기준으로 합쳐진 집합이 아닌 것을 의미합니다. 따라서 항상 root1 을 root2 의 부모로 정하거나 그 반대로 수행하는 고정방향 방식을 사용해야 합니다. 따라서 해당 예시에서는 항상 root1 이 root2 의 부모로 정하는 방식을 사용합니다.

## Implemention
Union Find 를 코드로 구현하면 다음과 같이 구현할 수 있습니다.

```python
def solution(mx_node, edges, s1, s2):  
  
    def find(n):  
        if tree[n] == n:  
            return n  
  
        return find(tree[n])  
  
    def union(n1, n2):  
        root1, root2 = find(n1), find(n2)  
        if root1 != root2:  # 사이클을 생성 여부를 판단하는 것이 아니면 불필요함.  
            tree[root2] = root1  
  
    tree = list(range(mx_node + 1))  # Tree 배열로 초기화  
    for n1, n2 in edges:             # Edges 들로 집합 A B 구성  
        union(n1, n2)  
  
    print('before :', *tree[1:], sep=' ')        # n1 n2 합치기 전 Tree 배열 확인  
    union(s1, s2)  
    print('after :', *tree[1:], sep=' ')         # n1 n2 합친 후 Tree 배열 확인  
  
mx_node = 9  # 모든 집합을 이루는 노드들 중 가장 큰 값  
edges = [  
    [3, 9],  
    [7, 3],  
    [2, 7],  
    [2, 5],  # 여기까지 집합 A 구성 (집합을 구성하는데도 union 사용)  
    [4, 8]   # 여기까지 집합 B 구성 (집합을 구성하는데도 union 사용)  
]  
s1 = 3  # 노드 3
s2 = 8  # 노드 8
solution(mx_node, edges, s1, s2)
```


output 은 다음과 같습니다. 앞서 살펴본 예제와 동일한 결과임을 확인할 수 있습니다.

```text
before : 1 2 7 4 2 6 2 4 3
after : 1 2 7 2 2 6 2 4 3
```


## 성능 문제
하지만 해당 코드의 `find` 함수에는 성능 이슈가 있습니다. 현재 코드는 트리의 깊이가 클 경우, 특히 `Degenerate Tree처럼 한쪽으로 치우친 구조에서는 O(N)까지 시간이 걸릴 수 있습니다`. 이 문제를 해결하기 위해 다음 두 가지 기법을 적용할 수 있습니다.

1. Path Compression (경로 압축)
	- find 연산 시, 방문한 모든 노드가 `직접 루트를 가리키도록 설정해서 다음 find를 더 빠르게 수행`하게 만듭니다.
2. Union By Rank (랭크 기반 유니온)
	- 항상 `더 작은 트리를 더 큰 트리 밑에 붙여서 트리의 깊이를 최소화`합니다.
	- 보통 `rank`는 트리의 "깊이"나 "크기"를 의미하는 배열을 따로 만들어 관리합니다.

#### 대표노드를 더 작게 유지
Union 연산을 수행할 때, `대표 노드 값이 더 작은 쪽을 루트(대표 노드)로 유지`하도록 합칠 수 있습니다.

- `"값이 더 큰 대표 노드의 부모를 더 작은 대표 노드로 설정한다"` 이 부분이 너무나도 중요합니다.
- 의사코드로는 `Disjoint[더 큰 대표노드] = 더 작은 대표노드` 로 표현할 수 있습니다.

#### 대표노드를 더 크게 유지

- `"값이 작은 대표 노드의 부모를 더 큰 대표 노드로 설정한다"`고 말할 수 있습니다. 이 부분이 너무나도 중요합니다.
- 의사코드로는 `Disjoint[더 작은 대표노드] = 더 큰 대표노드` 로 표현할 수 있습니다.
