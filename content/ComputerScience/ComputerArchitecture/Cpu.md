## CPU
CPU 는 메모리에 저장된 명령어를 읽고 해석하고 실행한다.

## CPU 의 구성
1. 산술논리연산장치 (ALU)
2. 제어장치 (Controll Unit : CU)
3. 레지스터 셋 (Register Set)

![](ComputerScience/ComputerArchitecture/images/Pasted%20image%2020241222213504.png)

## ALU 
ALU 는 CPU 내부 구성 요소 중 하나로, 덧셈, 뺄셈, 곱셈, 나눗셈, 논리 연산 등 계산을 위해 존재하는 부품 (계산용 회로)이다.

- ALU 는 CPU 연산에 필요한 `데이터를 받아들이고 값을 연산` 하는 역할을 한다. 구체적으로는 `레지스터로부터 피연산자를 받아들이고 제어장치로부터 제어 신호를 받아들인다`. 
- 연산이 끝나면 그 `결과값(0 과 1로 표현된 숫자, 문자 혹은 주소)`을 내보내게 되는데 이 결과값은 `레지스터`에 담아지게 된다. 이 레지스터를 바탕으로 메모리에 쓰거나 다른 레지스터와의 연산을 하게 된다. 또한, ALU 는 결과값 뿐만 아니라 연산결과 대한 부가정보로 `Flag 정보`도 내보내게 되는데 이는 `플래그 레지스터` 에 저장된다.


![](ComputerScience/ComputerArchitecture/images/Pasted%20image%2020241222212850.png)

> [!note] 연산 결과를 메모리가 아닌 레지스터에 담는 이유
> Memory  는 CPU 밖에 위치한다. 이와 달리 레지스터는 CPU 의 구성요소이기 때문에 CPU 내부에 위치한다. 상식적으로 생각해보아도 Memory 에 접근하는 속도보다 Register 에 접근하는 것이 더 빠르기 때문에 레지스터에 연산 결과를 담게 된다.

### Flag 종류
ALU 는 결과값 뿐만 아니라 연산결과 대한 부가정보로 `Flag 정보`도 내보내게 된다. 대부분의 CPU 가 공통적으로 포함하고 있는 Flag 종류는 다음과 같다.


**부호 플래그**
- 연산한 결과의 부호를 나타낸다.
- 플래그가 1이면 음수, 0이면 양수를 의미한다.

**제로 플래그**
- 연산 결과가 0 인지 여부를 나타낸다.
- 플래그가 1이면 결과가 0, 0일경우 결과가 0이 아님을 의미한다.

**캐리 플래그** 
- 연산 결과가 올림수나 빌림수가 발생했는지를 나타낸다.
- 플래그가 1이면 자리 올림수 혹은 빌림수가 발생했음을 의미하고, 0이면 발생하지 않았음을 의미한다.

**오버플로우 플래그** 
- 오버플로우(연산결과가 레지스터의 크기보다 커 값을 담을 수 없다는 정보)가 발생했는지를 나타낸다.
- 플래그가 1이면 오버플로우 발생, 0이면 발생하지 않음을 의미한다.

**인터럽트 플래그** 
- 인터럽트가 가능한지를 나타낸다.
- 플래그가 1이면 인터럽트가 가능함을 의미하며, 0이면 인터럽트가 불가능함을 의미한다.
- 운영체제와 관련된 내용이다.

**슈퍼바이저 플래그**
- 현재 모드가 커널모드인지 사용자모드로 실행중인지를 나타낸다.
- 플래그가 1이면 커널모드로 실행중임을 의미하며, 0이면 사용자모드로 실행중임을 의미한다.
- 운영체제와 관련된 내용이다.

## Controll Unit
Controll Unit (제어장치) 는 컴퓨터 부품들을 관리하고 작동시키기 위한 전기신호인 `제어신호` 를 발생시키고, `명령어를 해석`하는 장치이다.

![](ComputerScience/ComputerArchitecture/images/Pasted%20image%2020241222223014.png)

### 받아들이는 신호
1. `클럭 신호` 를 받아들인다.
2. `IR(Instruction Register)` 로 부터 해석할 명령어를 받아들이고, 그 명령어를 해석해서 제어신호를 내보낸다.
3. IR 로부터 받아들인 명령어를 해석하는 과정에서 부가정보가 필요할 수 있기 때문에  `Flag Register` 로부터 Flag 를 받아들인다.
4. 외부로부터 들어온 `제어신호` 를 받아들인다. (제어신호는 CPU 의 제어장치 뿐만 아니라 입출력장치를 비롯한 제어장치들도 제어신호를 발생시킬 수 있다.)

> [!note] 클럭
> 클럭이란 컴퓨터의 모든 부품을 움직일 수 있게 하는 시간 단위를 말한다. 이 클럭 신호 단위에 맞춰서 명령이 실행된다. (ex. Memory 에서 명령어를 가져오기)

![](ComputerScience/ComputerArchitecture/images/Pasted%20image%2020241222220744.png)

### 내보내는 신호
제어장치는 IR(Instruction Register) 로 받아들인 명령어를 해석하여 제어신호를 내보내게 되는데 크게 `CPU 내부, 외부`에 내보낸다.

**CPU 내부**
- ALU 에 수행할 연산 제어신호를 내보낸다.
- 레지스터 간에 데이터를 이동시키거나 해석하기 위한 제어신호를 레지스터에 내보낸다.

**CPU 외부**
- 메모리에 저장된 값을 읽고 싶을 땐 메모리를 향해 `메모리 읽기라는 제어신호`를 보낸다. (가져온 값은 레지스터에 저장된다.)
- 메모리에 어떤 값을 저장하고 싶을 땐 메모리를 향해 `메모리 쓰기라는 제어신호`를 보낸다.
- 입출력 장치의 값을 읽거나 쓰기 위한 제어신호

![](ComputerScience/ComputerArchitecture/images/Pasted%20image%2020241222222923.png)

## Register Set
Register(레지스터)는 `CPU 내부의 작은 임시저장장치`이다. 프로그램 속 명령어와 데이터는 실행 전후로 레지스터에 저장된다. CPU 안에는 여러 개의 레지스터가 존재하고, 각기 다른 이름과 역할을 가지고 있다. 그리고 이 Register 들의 집합을 Register Set 이라고 한다.

### Register 종류
레지스터의 종류는 CPU 개수와 종류 모두 다르다.  그래도 대부분의 CPU 가 공통적으로 사용하는 CPU 가 있다.

**Program Counter**
- `프로그램 카운터(PC)` 라고 불리며 메모리에서 가져올 다음 명령어의 주소를 저장하는 레지스터이다.

**Instruction Register**
- `명령어 레지스터(IR)` 라고 불리며 현재 수행할 명령어의 주소를 저장하는 레지스터이다. (CPU 로 이미 읽어들인 명령어)
- Controll Unit(제어장치) 가 IR 의 명령어를 받아들여서 해석하고, 제어신호를 보내게 된다.

**Memory Address Register**
- `메모리 주소 레지스터(MAR)` 라고 불리며 메모리의 주소를 저장하는 레지스터이다.
- CPU 가 읽어 들이고자 하는 주소를 주소 버스로 보낼 때 거치는 레지스터이다. (CPU 가 읽어 들이고자 하는 주소값을 주소 버스로 주고 받는다)

**Memory Buffer Register**
- `메모리 버퍼 레지스터(MBR)` 라고 불리며 메모리의 값을 저장하는 레지스터이다.
- CPU 가 정보(데이터와 명령어)를 데이터 버스로 주고받을때 거치는 레지스터이다.

**Flag Register**
- 플래그 레지스터라고 불리며 ALU 가 보낸 플래그 값이 저장된다.

**General Purpose Register**
- `범용 레지스터` 라고 불린다.
- 이름 그대로 다양하고 일반적인 상황에서 자유롭게 사용할 수 있는 레지스터이며 여러 종류가 있다.
- 주소, 명령어, 데이터 모두 담을 수 있다.

**Stack Pointer**
- Stack 의 꼭대기를 가리키는 레지스터이다. (스택이 어디까지 차 있는지에 대한 표시)
- Stack 과 Stack Pointer 를 이용한 주소지정 방식인 `스택 주소 지정 방식`에서 사용된다.

**Base Register**
- `변위 주소 지정 방식` 에서 사용되는 레지스터이며, 변위 주소 지정 방식에서 `기준 주소를 담고 있는 레지스터`이다.
- 변위 주소 지정 방식은 `Operand 필드의 값`과 `특정 레지스터의 값`을 더하여 유효주소를 얻는내는 주소 지정 방식이다.
- 변위 주소 지정 방식에서 사용되는 특정 레지스터가 베이스 레지스터이며, 이는 변경될 수 있다.

## 명령어 사이클
CPU 는 메모리로부터 명령어나 데이터를 갖고와서 실행하고 값을 저장할 수 있다. 이렇게 데이터를 가져오거나 명령어를 실행하는 과정은 모두 정형화된 Cycle 이 있다. 이 사이클을 `명령어 사이클`(Instruction Cycle) 이라고 한다. 명령어 사이클는 크게 `인출 사이클`, `간접사이클`, `실행 사이클`, `인터럽트 사이클` 로 구분되며 이 두가지 사이클이 반복되며 실행된다.

> 다시말해 명령어 사이클은 컴퓨터에서 명령어를 처리하는 정형화된 사이클이다.

![](ComputerScience/ComputerArchitecture/images/Pasted%20image%2020241228225713.png)

> [!note] 간접 사이클
> CPU 로 명령어를 인출해와도 메모리 접근이 더 필요하여 바로 실행이 불가능할 떄가 있다. 대표적인 예삭 간접 주소 지정 명령어를 사용했을 때이다. 해당 경우에는 인출 -> 간접 -> 실행 순으로 실행되게 된다.

### 인출 사이클
메모리에 저장된 값을 CPU 내부로 값고오는 것을 `인출` 이라고 하며, `메모리의 데이터를 CPU 로 가져오는 주기`를 인출 사이클 이라고 한다.

![](ComputerScience/ComputerArchitecture/images/Pasted%20image%2020241228205642.png)

###  실행 사이클
메모리에서 데이터와 명령어를 CPU 로 가져왔으면 `실행` 해야한다. 즉, 실행 사이클은 `CPU에서 명령어를 실행하는 사이클` 이다.

![](ComputerScience/ComputerArchitecture/images/Pasted%20image%2020241228205653.png)

## 인터럽트
CPU 는 정해진 흐름(명령어 사이클) 에 맞춰 데이터를 가져오거나 명령어를 실행한다. 이러한 흐름을 방해하는 신호를 `인터럽트(Interrupt)`라고 한다.

> 인터럽트는 CPU 가 꼭 주목해야할때 혹은 먼저 처리해야할 작업이 생겼을 때 발생한다.

### 인터럽트 종류

**동기 인터럽트**
- 예외라고 불리며, CPU 가 예기치 못한 상황을 접했을 때 발생한다.
- 실행중인 명령어 사이클을 멈추고, 예외를 먼저 처리하게 된다.

**비동기 인터럽트**
- 하드웨어 인터럽트라고 불리며, 주로 입출력장치에 의해 발생하는 인터럽트이다.
- CPU 가 `입출력 작업 도중에도 효율적으로 명령어를 처리`하기 위해 사용된다.
- 하드웨어 인터럽트가 없다면, CPU 는 프린터와 같은 입출력 장치에게 주기적으로 작업 완료 여부에 대한 신호를 보내야한다. 하지만 `하드웨어 인터럽트가 있다면, 입출력 작업 동안 CPU 는 다른 일을 할 수 있게 된다.`

![](ComputerScience/ComputerArchitecture/images/Pasted%20image%2020241228222148.png)

### 비동기 인터럽트 처리 순서
1. IO 장치는 CPU 에 `인터럽트 요청 신호`를 보낸다.
2. CPU 는 실행 사이클이 끝나고 명령어를 인출하기 전 항상 인터럽트 여부를 확인한다.
3. CPU 는 인터럽트 요청을 확인하고 `인터럽트 플래그`를 통해 현재 인터럽트를 받아들일 수 있는지 여부를 확인한다.
4. 인터럽트를 받아들일 수 없다면 CPU 는 지금까지의 작업을 백업한다.
5. CPU 는 `인터럽트 벡터`를 참조하여 `인터럽트 서비스 루틴`을 실행한다.
6. 인터럽트 서비스 루틴 실행이 끝나면 백업해둔 작업을 복구하여 실행을 재개한다.

![](ComputerScience/ComputerArchitecture/images/Pasted%20image%2020241228230953.png)


> [!note] 인터럽트 처리
> CPU 가 인터럽트를 처리한다는 것은 인터럽트 서비스 루틴을 수행하고, 본래 수행하던 작업으로 다시 되돌아오는 것을 의미한다. 보다 정확히는 인터럽트 서비스 루틴으로 Jmp 하기 전, 레지스터(PC, IR 등) 내용들을 모두 Stack 에 백업해두고, 인터럽트를 처리한다. 처리가 완료되면 Stack 의 내용들을 pop 하여 인터럽트 서비스 루틴을 실행하기 전 상황으로 복귀하게 된다.


**인터럽트 요청 신호**
- CPU 의 작업을 방해하는 인터럽트에 대한 요청이다.
- CPU 에게 "지금 끼어들어도 되냐?" 는 요청을 보내는 신호라고 생각하면 된다.

**인터럽트 플래그**
- Flag Register 안에 저장된 Flag 의 한 종류이며, 인터럽트 요청을 받아들일지 무시할지를 결정하는 Bit 이다.
- 인터럽트 플래그로 막을 수 없는 인터럽트를 막을 수 없는 인터럽트 (Non Maskable Interrupt) 라고 한다.
  
**인터럽트 벡터**
- 인터럽트 서비스 루틴의 시작 주소를 포함하는 인터럽트 서비스 루틴의 식별 정보.
- 각각의 인터럽트를 구분하기 위한 정보이며 CPU 가 해당 인터럽트 서비스 루틴의 시작 주소를 알기 위해 필요하다.
  
**인터럽트 서비스 루틴**
- 인터럽트가 발생했을 때 해당 `인터럽트를 어떻게 처리하면 되는지가 적혀있는 프로그램`
- 프로그램이기 때문에 메모리에 저장된다.
- 인터럽트를 보내는 주체(프린터, 키보드)에 따라서 각기 다른 인터럽트 서비스 루틴의 시작주소를 갖고 있다.
